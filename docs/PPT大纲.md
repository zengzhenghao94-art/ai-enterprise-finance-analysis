## P1：问题定义 — 经营分析为什么需要 AI？

**标题**：从 3 天到 3 秒 —— 经营分析的效率革命

**内容要点**：

### 场景：月度经营分析会
- 每月一次，管理层 + 各部门负责人参加
- 财务人员会前准备：导出数据 → Excel 透视 → 手写报告 → 做 PPT
- **耗时 2-3 天**，管理层想临时追问一个数据 → 至少等 20 分钟

### 三个核心痛点（配图标/图示）
1. 🔴 **效率低**：数据查询靠人肉写 SQL/Excel，临时问题响应慢
2. 🟠 **异常滞后**：靠月底报表才能发现异常，已滞后 2-4 周
3. 🟡 **质量不稳**：不同人写的分析报告深度参差不齐

### 设计建议
- 左半：传统流程图（导出→整理→分析→写报告→做PPT，标注"2-3天"）
- 右半：一个大问号 → "能不能让 AI 来做？"
- 底部一行字：三个子任务 → 异常检测 | 自然语言查数 | 自动报告

## P2：AI 解决方案 — 三层 AI 架构

**标题**：两个 AI 技术、三个角色、一条完整链路

**内容要点**：

### 技术架构图（核心视觉）
```
┌─────────────────────────────────────────────┐
│              Vue 3 前端（对话 + 图表 + 简报）   │
├─────────────────────────────────────────────┤
│          FastAPI 后端（7 个 API 端点）         │
├──────────┬──────────┬───────────────────────┤
│ SQLite   │ ML 引擎  │ LLM 引擎（通义千问）    │
│ 经营数据 │ Isolation│ ├─ NL2SQL 翻译         │
│ 3部门    │ Forest   │ ├─ 数据解释            │
│ ×12月    │ 异常检测  │ └─ 简报生成            │
└──────────┴──────────┴───────────────────────┘
```

### 三个 AI 角色
| 角色 | 技术 | 做什么 |
|------|------|--------|
| 🛡️ 数据哨兵 | Isolation Forest (ML) | 9维度自动发现异常，实时预警 |
| 🌉 数据翻译官 | LLM (通义千问) | 自然语言→SQL→查询结果→解释 |
| 📝 报告写手 | LLM (通义千问) | 数据→Markdown 管理层简报 |

### 设计建议
- 架构图占页面 60% 面积，三个角色用图标+一句话标注
- 底部标注技术栈：Python FastAPI / Vue3+ECharts / scikit-learn / 通义千问

## P3：AI 角色详解 + 传统 vs AI 对比

**标题**：AI 扮演什么角色？为什么非 AI 不可？

**内容要点**：

### 上半页：三个子任务演示截图（横向排列）
1. ChatPanel 截图：输入"销售部上半年收入"→ SQL + 结果表格 + AI 解释
2. AnomalyAlert 截图：红色/橙色高亮异常指标列表
3. ReportPanel 截图：自动生成的 Markdown 简报

### 下半页：传统 vs AI 对比表（核心答辩素材）
| 维度 | 传统方式 | AI 方式 | 提升 |
|------|---------|--------|:---:|
| 数据查询 | 手工 Excel，≥20分钟 | 自然语言，5秒 | **240x** |
| 异常发现 | 月底报表，滞后2-4周 | 实时检测，即入库即发现 | **实时** |
| 报告生成 | 人工 2-3天 | AI 3秒初稿 | **86,400x** |
| 监测维度 | 人工 3-5个指标 | ML 9维度同时监测 | **2-3x** |
| 一致性 | 因人而异 | Prompt 模板保证统一 | — |

## P4：业务价值 — 量化成果

**标题**：业务价值量化 —— 效率 · 准确率 · 风险控制

**内容要点**：

### 三个价值维度（卡片式布局）

**⚡ 效率**
- 经营分析准备周期：2-3天 → 5分钟
- 临时数据查询：20分钟 → 5秒
- 财务人员时间释放：从"做表"到"做分析"

**🎯 准确率**
- SQL 三层安全校验：关键字白名单 + SELECT-only + 语法校验
- 标准财务查询场景准确率 >80%
- 杜绝手工 SQL 的拼写错误和逻辑漏洞

**🛡️ 风险控制**
- 异常发现从"滞后月报"到"实时预警"
- 9 个财务维度全量监测（6原子+3派生）
- 高危异常第一时间推送管理层

### 底部：一句话总结
> "不是用 AI 包装传统流程，而是重构了'数据→洞察→决策'的完整链路"

### 设计建议
- 三列卡片布局，每列一个图标 + 数字 + 说明
- 用"之前 vs 之后"的对比数字，强调倍数提升

## P5：总结与展望

**标题**：让人做决策，让 AI 做剩下的

**内容要点**：

### 核心回顾
- 🛡️ **数据哨兵**（ML异常检测）→ 从滞后到实时
- 🌉 **数据翻译官**（NL2SQL）→ 从 SQL 到自然语言
- 📝 **报告写手**（简报生成）→ 从 3 天到 3 秒

### 方案亮点
- 两层 AI（ML + LLM），互为补充不重叠
- 完整可运行原型，非 PPT 概念
- 答辩现场可实时演示

### 未来方向（2-3 条）
- 接入真实 ERP 数据源（用友/金蝶）
- 增加预算对比和 predictive forecasting
- SSE 流式响应——让 AI "边想边写"

### 设计建议
- 简洁收尾，不要堆文字
- 三个 AI 角色用图标+一句话回顾
- 底部放团队信息 + 感谢
